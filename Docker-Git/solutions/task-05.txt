Task 05: Optimizing Docker Images with Multi-stage Builds

Project:
Docker-Git/task-05

Application:
TypeScript + Express, Node.js 24.x


1. Application

Created a simple TypeScript Express server.

File:
src/index.ts

The server listens on port 3000 and returns:

Hello from TypeScript Docker!


2. Single-stage Dockerfile

File:
Dockerfile.single

Content:

FROM node:24

WORKDIR /app

COPY package*.json ./

RUN npm install

COPY tsconfig.json ./
COPY src ./src

RUN npm run build

EXPOSE 3000

CMD ["npm", "start"]


Build command:

docker build -t ts-node-single:v1 -f Dockerfile.single .


Image size:

DISK USAGE: 1.7GB
CONTENT SIZE: 424MB


3. Multi-stage Dockerfile

File:
Dockerfile

Content:

FROM node:24 AS builder

WORKDIR /app

COPY package*.json ./

RUN npm install

COPY tsconfig.json ./
COPY src ./src

RUN npm run build


FROM node:24-alpine AS production

WORKDIR /app

COPY package*.json ./

RUN npm install --omit=dev

COPY --from=builder /app/dist ./dist

EXPOSE 3000

CMD ["node", "dist/index.js"]


Build command:

docker build -t ts-node-multi:v1 .


Image size:

DISK USAGE: 253MB
CONTENT SIZE: 63.6MB


4. .dockerignore

File:
.dockerignore

Content:

node_modules
dist

.git
.gitignore

*.log
*.md
Dockerfile.single


The source directory and TypeScript files were not excluded because they are required by the builder stage to compile the application.


5. Image comparison

Single-stage:

ts-node-single:v1
DISK USAGE: 1.7GB
CONTENT SIZE: 424MB


Multi-stage:

ts-node-multi:v1
DISK USAGE: 253MB
CONTENT SIZE: 63.6MB


The multi-stage image is approximately 6.7 times smaller than the single-stage image.


6. Effect of .dockerignore

Built:

docker build -t ts-node-multi:v2 .

The build context was reduced to approximately 160 bytes.

The resulting image size remained:

DISK USAGE: 253MB
CONTENT SIZE: 63.6MB

This is expected because .dockerignore reduces the Docker build context, while the final multi-stage image already contains only production dependencies and compiled files.


7. Testing

Started the container:

docker run -d --name ts-node-multi-v2 -p 3001:3000 ts-node-multi:v2

Tested:

curl http://localhost:3001

Result:

HTTP 200 OK

Hello from TypeScript Docker!


8. Conclusion

The multi-stage Docker build separates the build environment from the production environment.

The builder stage uses the full node:24 image and development dependencies to compile TypeScript.

The production stage uses node:24-alpine, installs only production dependencies and copies only the compiled dist directory.

This significantly reduces the final Docker image size and excludes unnecessary build tools and source files from the production image.
